# dev-harness — видение

## Зачем отдельный репозиторий

Ядро цикла (`plan → code → gates → review → evaluate → decide`) выросло внутри одного проекта и
переиспользуется другими. Держать его копией в каждом проекте значит чинить одни и те же дефекты по
нескольку раз и расходиться в поведении.

`dev-harness` отделяет **механизм** от **политики**:

- механизм (ядро): детерминированные скрипты, схема артефактов, переходы автомата, сборка
  свидетельств, PR-тело, метрики, evals;
- политика (проект): какие гейты запускать, какие лимиты и пути, какой провайдер моделей, какие роли
  и запреты — в `.pi/harness.config.json` и `AGENTS.md` проекта.

Ядро не содержит названий проектов, их пакетов и каталогов. Это проверяется grep'ом и тестами.

## Что входит в v0.1

- Конфиг-слой `.pi/harness.config.json`: гейты, лимиты, пути, evals, провайдер, тайм-ауты; строгая
  валидация с кодом 2.
- CLI ядра: `cycle-gates`, `cycle-decide`, `cycle-state`, `cycle-evidence`, `cycle-usage`,
  `cycle-metrics`, `cycle-report`, `cycle-pr-body`.
- `check-harness` (правила H1–H6) и evals-инструменты (`evals-collect`, `evals-cost`, `evals-pack`,
  `evals-score`).
- Норматив протокола: `docs/protocol.md`, `docs/orchestrator-core.md`, `docs/orchestrator.md`.
- Шаблоны `.pi/agents/*`, `.pi/prompts/cycle.md`, пример конфига.
- Самодостаточность: собственные `.pi/settings.json`, `.pi/agents/*`, `.pi/harness.config.json` и
  зелёные `node --test` / `prettier --check`.

## Что не входит в v0.1

- Bootstrap-скрипт, который сам создаёт `.pi/` и конфиг в проекте.
- Web UI для просмотра циклов.
- nginx/прокси и любая серверная обвязка.
- MCP-сервер и интеграции с внешними трекерами.
- Параллельный запуск стадий и оркестратор вместо LLM-супервизора (фаза 3).
- Миграция проектов: перенос делает проект-потребитель, dev-harness только поставляет ядро.

## Принципы

1. **Детерминизм.** Никаких дат генерации и случайности; артефакты нормализуются по ключам.
2. **Код решает, а не текст.** Решение `cycle-decide` — машинный артефакт, а не просьба.
3. **Свидетельства важнее отчётов.** Оценщик видит `evidence/`, а не план и не отчёт кода.
4. **Секреты не печатаем.** Диагностика не содержит содержимого `.env*`.
5. **Правила проекта — в конфиге.** Ядро не знает ни одного гейта конкретного проекта.
