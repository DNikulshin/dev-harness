# 0002. Строгая типизация: JavaScript + JSDoc + `tsc`, без сборки

- **Статус:** принято
- **Дата:** 2026-11-19
- **Контекст:** ядро — 52 модуля `.mjs` с JSDoc-аннотациями (741 `@param`, 481 `@returns`, 34
  `@typedef`), но **аннотации никем не проверяются**: `tsconfig` нет, `@ts-check` не включён,
  `.d.ts` в пакете отсутствует. Прогон `tsc --noEmit --checkJs` на копии репозитория дал 460 ошибок:
  345 в коде и 115 в тестах, из них ~250 — долг аннотаций (значения из `JSON.parse` и `readJson` без
  сужения), а ~90 — уже сигнал о хрупкости: null-ветки, индексация `Readonly<{ENOENT: ...}>`
  строкой, несовпадения форм объектов. Артефакты цикла (`state.json`, `gates.json`, `decision.json`,
  `metrics.json`) — это контракт между скриптами, и расхождение в них сейчас ловится только тестами.
  Ограничения: рантайм остаётся plain ESM (правило 5 `AGENTS.md`), установка пакета по git-тегу не
  должна ничего собирать, поведение и детерминизм меняться не должны.

## Решение

**(а) Код остаётся `.mjs`.** Источник типов — JSDoc; проверка — `tsc --noEmit` с `allowJs`,
`checkJs` и `strict`. Переезд на `.ts` не даёт сверх этого ничего: Node стирает типы, но не
проверяет их, значит `tsc` нужен в любом случае, а миграция ломает публичные спецификаторы импорта
уже выпущенного пакета.

**(б) Строгий набор флагов** (`tsconfig.json`): `strict`, `noUncheckedIndexedAccess`,
`erasableSyntaxOnly: true`, `noEmit`, `module`/`moduleResolution`: `nodenext`, `types: ["node"]`,
`skipLibCheck`. `erasableSyntaxOnly` держит открытой дверь в `.ts`: синтаксис, который нельзя
стереть (`enum`, `namespace`, parameter properties), запрещён уже сейчас.

**(в) `typescript` и `@types/node` — только devDependencies.** Рантайм-зависимостей остаётся ноль;
установка пакета у потребителя не тянет компилятор.

**(г) Гейт `typecheck`** включён в `.pi/harness.config.json` (`gates`) и в CI **зелёным**, то есть
после burn-down. Гейт с baseline-списком игноров запрещён: он создаёт видимость проверки. Порядок:
сначала код, затем тесты.

**(д) Политика использования типов:**

1. `any` запрещён; для неизвестных данных — `unknown` и сужение.
2. `@ts-expect-error` — только с причиной и ссылкой на issue; `@ts-ignore` запрещён.
3. Типы не заменяют рантайм-валидацию: конфиг и артефакты с диска проверяются
   `validate.mjs`/`loadConfig`, как и раньше. Типы защищают код, валидаторы — данные.
4. Типы перечислений выводятся из существующих констант (`typeof STAGES[number]`), а не дублируются
   вторым списком.

**(е) Типы для потребителя пакета.** `.d.ts` эмитятся из JSDoc (`declaration` +
`emitDeclarationOnly`) и **коммитятся** в репозиторий; CI проверяет актуальность (пересборка +
`git diff --exit-code`). `prepare`/`prepack` при установке не используются: установка по git-тегу не
должна ни собирать, ни тянуть devDependencies.

## Последствия

- Положительные: контракт артефактов проверяется компилятором, а не только тестами; у потребителя
  появляются типы без сборки; ошибки вида «свойство не существует» и «возможно `null`» ловятся до
  запуска.
- Отрицательные / цена: ~460 ошибок надо разобрать один раз; JSDoc-эргономика хуже, чем синтаксис TS
  (`import('./x.mjs').T` вместо `import type`); `noUncheckedIndexedAccess` требует явных проверок
  там, где код полагался на «массив непустой».
- Что становится запрещено: добавлять `.mjs` без JSDoc к экспортируемым функциям; использовать `any`
  и `@ts-ignore`; включать гейт с исключениями вместо починки; собирать типы при установке.

## Рассмотренные альтернативы

| Вариант                                        | Плюсы                                 | Минусы                                                                                   |
| ---------------------------------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------- |
| `.ts` напрямую (Node стирает типы, без сборки) | нативный синтаксис, без JSDoc-обёрток | переименование 52 файлов, `.ts` в спецификаторах, `import('/path.ts')` у потребителя     |
| `.ts` + сборка в `dist/`                       | гарантированные `.d.ts`, старые Node  | два артефакта, sourcemap, «что в репо vs что в пакете», сборка при установке из git      |
| Оставить JSDoc как комментарии (статус-кво)    | нулевая цена сейчас                   | 34 typedef и 741 аннотация не проверяются; хрупкость в null-ветках остаётся незамеченной |
