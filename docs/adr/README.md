# ADR — решения об устройстве dev-harness

Шаблон и правило «решение с последствиями и запретами» перенесены из проекта-источника
(`docs/adr/`), чтобы механизм принятия решений не разъезжался между проектами.

| Номер                                        | Решение                                                              | Статус     |
| -------------------------------------------- | -------------------------------------------------------------------- | ---------- |
| [0001](./0001-product-layout.md)             | Нейтральное ядро, профили, три класса артефактов, манифест           | принято    |

## Правила ведения

1. ADR фиксирует **решение и его цену**, а не план работ: план живёт в issue.
2. Принятое ADR не переписывается. Отмена или замена — новое ADR со статусом «заменено» в старом.
3. Если правило можно проверить механизмом (гейт, тест, `check-harness`), ADR ссылается на проверку.
   Правило, которое проверяется глазомером, в норматив не попадает.
