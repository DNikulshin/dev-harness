# Актуальный контекст через local-rag

Правило для проекта, который подключает harness: как искать решения по документации и как держать
индекс в согласии с файлами. Скрипт автоматизации сюда не входит — он знает про машину (версия
MCP-сервера, путь к базе, общий индекс нескольких проектов), поэтому живёт в репозитории, а не в
пакете (ADR [0003](./adr/0003-environment-infrastructure.md)). Проект приносит себе правило, а не
копию скрипта.

Документ самодостаточен: чтобы им пользоваться, не нужен другой репозиторий. Происхождение
зафиксировано в конце — откуда правило пришло.

## Зачем

Знание о документах стареет молча: агент помнит версию `docs/` недельной давности и принимает
решения по устаревшему тексту. Индекс, синхронизированный в начале и в конце сессии, делает
источником файлы, а не воспоминания о них.

## В начале сессии

1. Определи корень репозитория (`git rev-parse --show-toplevel`). Если доступен MCP `local-rag`,
   запусти `local-rag_sync_start` только для `<корень>/docs` и дождись конечного состояния через
   `local-rag_sync_status`. Это обновит изменённые документы и удалит из индекса те, которых больше
   нет. Исключение — `BASE_DIR` сервера указывает на каталог портфеля, а не на проект: тогда
   синкается портфель целиком, а проекты разделяются `scope` (см. «Раскладка базы»).
2. Получив задачу, ищи релевантные решения через `local-rag_query_documents` со `scope=<корень>` и
   конкретным запросом по задаче. По всей базе без `scope` не ищи: база общая для нескольких
   проектов.
3. Результаты — навигация к источникам, а не замена им: `AGENTS.md`, код и актуальные файлы `docs/`
   остаются истиной. При важном решении открой файл напрямую.
4. RAG недоступен или синхронизация упала — не блокируйся: читай нужные файлы `docs/` напрямую
   (`grep`, `find_files`, `read`), выполни задачу и **явно** скажи, что сработал fallback и почему.
   Молча деградировать нельзя: результат без пометки выглядит как проверенный по индексу.

## В конце сессии

Повтори `local-rag_sync_start` по `<корень>/docs` и проверь `local-rag_sync_status`: правки
документов этой сессии должны попасть в индекс. Если RAG недоступен и в конце — напиши в итоге, что
синк не выполнен и почему; то, что уже в `main`, подхватит `post-merge` при следующем `git pull`.

## Что индексируется

Только `docs/` этого репозитория. Не весь репозиторий и не общий `/home/dev/projects/`: база общая
для нескольких проектов, и синк корня одного проекта перетирает чужие документы.

Не отправляй в RAG: `.env*`, пользовательские данные, `node_modules`, generated-файлы,
`.pi/artifacts/` (артефакты циклов — рабочий мусор, а не документация), дампы и бандлы данных
(`*.txt` вида `certdata.txt`), кэши сборки и окружений (`out/`, `coverage/`, `.cache/`, `.venv/`,
`target/`).

### Раскладка базы

Что синкать, решает `BASE_DIR`/`BASE_DIRS` MCP-сервера, а не привычка:

| `BASE_DIR`                     | Что синкать                  | Как разделять проекты                                                  |
| ------------------------------ | ---------------------------- | ---------------------------------------------------------------------- |
| корень проекта                 | `<корень>/docs`              | нечем: в базе один проект, `scope` = `<корень>`                        |
| корень портфеля (`~/projects`) | портфель целиком, без `path` | только `scope` в запросе: `["<проект>/docs", "~/projects/.workspace"]` |

Полный синк портфеля не «перетирает» чужие документы, когда `BASE_DIR` — сам портфель: область
сверки совпадает с областью хранения. Перетирает он ровно в одном случае — `BASE_DIR` указывает на
проект, а в базе лежат документы другого: их пути вне области сверки, поэтому `sync` их не удалит,
но и не обновит. Отсюда правило: область сверки должна покрывать область хранения.

Список исключений живёт в `tooling/rag-sync.mjs` (`IGNORE_PATTERNS` → `IGNORE_PATHS`) и уходит в
`mcp-local-rag`: это страховка на случай **полной** сверки без явного пути — `BASE_DIRS` по
умолчанию — весь `~/projects`, — а не замена правилу из таблицы выше. Список собран по замеру, а не
«на всякий случай»: в базе на 597 документов недокументация занимала 60 % чанков — артефакты циклов
30 %, `*.txt` 22 % (`certdata.txt` — 3833 чанка), `node_modules` 10 %, `out/` и `coverage/` 3 %
(issue [#173](https://github.com/DNikulshin/dev-harness/issues/173)).

Исключение не чистит уже проиндексированное: `mcp-local-rag@0.23.0` (`dist/features/sync.js`,
`planSync`) считает строку сохранившейся, если её путь попал под `excludePaths`, то есть шаблон
защищает старую запись от удаления (issue #169). После расширения списка грязь остаётся, и убирают
её явно:

- пересобрать индекс: остановить MCP-сервер, удалить `DB_PATH` (по умолчанию
  `~/.local/share/mcp-local-rag/lancedb`), запустить полный синк — детерминированно, без перебора
  путей;
- либо точечно `local-rag_delete_file` по путям.

Проверить фактический состав базы: `local-rag_status` (документы и чанки) и `local-rag_list_files`
со `scope` — `ingested: true` показывает, что реально лежит в индексе.

## Автоматизация (по желанию проекта)

Индекс можно обновлять без агента: хук `.githooks/post-merge` вызывает `pnpm rag:sync` после
`git pull`/merge, то есть сразу после смерженного PR. Требования к такой автоматизации:

- синхронизирует только `docs/`;
- никогда не блокирует `pull`: проблема — предупреждение и код 0;
- версия MCP-сервера в скрипте совпадает с той, что в конфиге MCP; расхождение меняет модель
  эмбеддингов и формат индекса;
- если MCP-сервер держит LanceDB, синк может не пройти — тогда синхронизируй через
  `local-rag_sync_start` или повтори позже.

Хуки включаются в клоне один раз: `git config core.hooksPath .githooks`. Настройка локальная, в
репозитории она не передаётся — поэтому это написано здесь, а не в скрипте.

## Происхождение

Правило перенесено из проекта-источника (`AGENTS.md`, раздел «Актуальный контекст через
local-rag`, и `scripts/rag-sync.mjs`): там оно обкатано на живом цикле. Отличие одно — здесь оно разложено на нормативный текст (этот файл, он же уезжает потребителю) и локальную инфраструктуру (`tooling/rag-sync.mjs`),
см. ADR [0003](./adr/0003-environment-infrastructure.md).
